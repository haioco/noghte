  2. مشخصات طرح

    1. توسعه و عرضه نقطه — اولین نقطه دسترسی ابری بومی ایران با قابلیت‌های SASE کامل (ZTNA، FWaaS، SWG) و رمزنگاری پساکوانتومی ترکیبی (Hybrid PQC) بر اساس استانداردهای NIST، همراه با هسته تحریم‌شکن داخلی برای اتصال امن سازمان‌ها به سرویس‌های تحریم‌شده.

      2. توسعه و عرضه نقطه — اولین نقطه دسترسی ابری بومی ایران با SASE کامل و رمزنگاری پساکوانتومی ترکیبی

    2. نقطه یک پلتفرم امنیت ابری جامع است که قابلیت‌های SASE (امنیت صفر-اعتماد، فایروال ابری، دروازه امن وب) را با رمزنگاری پساکوانتومی ترکیبی (ML-KEM-768، ML-DSA-65، SLH-DSA) و هسته تحریم‌شکن داخلی ادغام می‌کند. این محصول به سازمان‌ها و کاربران ایرانی امکان اتصال امن و بدون محدودیت به سرویس‌های تحریم‌شده را فراهم می‌کند، در حالی که در برابر تهدیدات کوانتومی آینده نیز مقاوم است. نقطه بر بستر عاملیت هایو اجرا می‌شود و جایگزین بومی برای Cloudflare WARP و راهکارهای خارجی (Zscaler، Cloudflare One) است که ایران را تحریم کرده‌اند.

نقطه یک پلتفرم امنیت ابری جامع است که قابلیت‌های SASE (ZTNA، FWaaS، SWG) را با رمزنگاری پساکوانتومی ترکیبی (ML-KEM-768، ML-DSA-65، SLH-DSA) و هسته تحریم‌شکن داخلی ادغام می‌کند. این محصول به سازمان‌ها و کاربران ایرانی امکان اتصال امن و بدون محدودیت به سرویس‌های تحریم‌شده را فراهم می‌کند، در حالی که در برابر تهدیدات کوانتومی آینده نیز مقاوم است. نقطه بر بستر عاملیت هایو اجرا می‌شود و جایگزین بومی برای Cloudflare WARP و راهکارهای خارجی است که ایران را تحریم کرده‌اند. مدت اجرا ۶ ماه، بودجه ۳۴ میلیون ریال، و سهم معاونت ۱۷ میلیون ریال (وام قابل تبدیل به بلاعوض).

مدت اجرا: ۶ ماه | مقیاس: پایلوت | استان: تهران | ستاد: توسعه اقتصاد دانش‌بنیان کوانتوم، لیزر و فوتونیک

    1. نقطه از سه لایه اصلی تشکیل شده است:
      ۱. کنترل‌پلن ابری: احراز هویت (Keycloak + MFA)، موتور سیاست‌گذاری (OPA)، مدیریت گواهی‌ها (HashiCorp Vault + PQC)، و داشبورد مدیریت (Grafana).
      ۲. لبه امنیتی (SSE): فایروال ابری (FWaaS) با eBPF/nftables، دروازه امن وب (SWG) با Squid+ICAP، دسترسی صفر-اعتماد (ZTNA) با گیت‌وی اختصاصی، و تونل WireGuard/TLS 1.3 هیبریدی با ML-KEM-768.
      ۳. کلاینت اندروید/دسکتاپ: اپلیکیشن کاربرپسند با اتصال یککلیکه، مدیریت ترافیک، و همگام‌سازی خودکار.

      هسته تحریم‌شکن داخلی با استفاده از Fake-IP DNS و لیست ۸۰۰+ دامنه تحریم‌شده (به‌روزرسانی خودکار)، ترافیک را به سرورهای امن هدایت می‌کند. رمزنگاری پساکوانتومی با رویکرد هیبریدی (کلاسیک + PQC) تضمین می‌کند که حتی در صورت کشف آسیب‌پذیری در الگوریتم‌های جدید، لایه کلاسیک همچنان محافظت فراهم کند. هدف کاهش ارزبری سالانه بیش از ۱ میلیون دلاری برای ۱۰۰۰۰ کاربر سازمانی و ایجاد ۵ اشتغال مستقیم + ۲ پشتیبانی است.

نقطه از سه لایه اصلی تشکیل شده است: ۱. کنترل‌پلن ابری (Keycloak + OPA + Vault + Grafana) ۲. لبه امنیتی (FWaaS با eBPF/nftables، SWG با Squid+ICAP، ZTNA با گیت‌وی اختصاصی، تونل WireGuard/TLS 1.3 هیبریدی با ML-KEM-768) ۳. کلاینت اندروید/دسکتاپ. هسته تحریم‌شکن داخلی با Fake-IP DNS و لیست ۸۰۰+ دامنه تحریم‌شده به‌روزرسانی خودکار، ترافیک را به سرورهای امن هدایت می‌کند. رمزنگاری پساکوانتومی با رویکرد هیبریدی (کلاسیک + PQC) تضمین می‌کند که حتی در صورت کشف آسیب‌پذیری در الگوریتم‌های جدید، لایه کلاسیک همچنان محافظت فراهم کند. فاز ۱: تثبیت تونل + PQC. فاز ۲: ZTNA + FWaaS + SWG. فاز ۳: کنترل‌پلن + CASB/DLP. فاز ۴: تست نفوذ + انطباق FIPS + انتشار ۱.۰.


معماری دسترسی چند-ترانسپورتی (Access Plane) — تفکیک نوع منبع از روش اتصال

در معماری نقطه، «نوع منبع (Resource)» از «روش اتصال (Transport)» تفکیک شده است؛ هسته تحریم‌شکن فعلی (تونل امن موجود) تنها یکی از ترانسپورت‌های سامانه است، نه مبنای کل معماری. این جداسازی تضمین می‌کند افزودن ترانسپورت‌های آینده (WireGuard، mTLS، HTTPS، SPICE، SSH) بدون تغییر مدل محصول ممکن باشد.

نگاشت منابع به ترانسپورت/گیت‌وی:

• Web Application → HTTPS Reverse Proxy

• REST/API → HTTPS + OIDC/mTLS

• سرویس TCP → TCP Gateway

• SSH → SSH Gateway

• GitLab → HTTPS/SSH Gateway

• پایگاه داده → TCP Gateway + سیاست هویت

• Kubernetes API → HTTPS Gateway

• ماشین مجازی ویندوز → SPICE Gateway

• ماشین مجازی لینوکس → SSH / SPICE

• شبکه خصوصی → Connector مبتنی بر WireGuard

• اتصال سایت‌به‌سایت → WireGuard/IPsec

• Agent → Connector با mTLS

سه جزء اصلی معماری:

۱) لایه کنترل (Control Plane): سامانه مدیریت هویت و RBAC (Keycloak) + کنترل‌پلن هایو برای مدیریت Resource/Access/Policy. ۲) لایه دسترسی (Access Plane): Access Controller + گیت‌وی‌های اختصاصی هر پروتکل (HTTPS، TCP، SPICE، SSH). ۳) لایه اتصال: Connector/Agent.

مدل Connector برای منابع خصوصی:

Connector درون شبکه مشتری نصب می‌شود و خودش اتصال امن خروجی (outbound) با mTLS به هایو برقرار می‌کند؛ در نتیجه مشتری برای هیچ منبعی نیازی به باز کردن پورت عمومی ندارد. این مدل برای پلتفرم PaaS هایو ارزش راهبردی دارد. در دسترسی به ماشین مجازی نیز SPICE Gateway مستقیماً در معرض اینترنت قرار نمی‌گیرد و در صورت نیاز پشت Private Connector قرار می‌گیرد (مسیر: کاربر → احراز هویت → هایو: Authorization/Session → SPICE Gateway → VM).

انتزاع API — تفکیک منبع از دسترسی:

هر درخواست دسترسی با دو فیلد «نوع منبع» و «پروتکل دسترسی» تعریف می‌شود و گیت‌وی در لایه پایین‌تر نحوه برقراری اتصال را تصمیم می‌گیرد:

{"resource": {"type": "vm", "name": "windows-dev"}, "access": {"protocol": "spice"}}

{"resource": {"type": "application", "name": "gitlab"}, "access": {"protocol": "https"}}

{"resource": {"type": "database", "name": "postgres"}, "access": {"protocol": "tcp"}}

پیوست ۳: طرح تجاری‌سازی

پیوست ۴: برآورد مالی تفصیلی

    • نقطه یک راهکار بومی و استراتژیک برای امنیت سایبری ایران است که هم‌زمان تحریم‌ها را دور می‌زند و آمادگی کوانتومی را تضمین می‌کند. اجرای این طرح نه‌تنها اشتغال و کاهش ارزبری ایجاد می‌کند، بلکه استقلال فناوری ملی را تقویت می‌کند.

  1. تكميل اين پرسشنامه به‌خودی‌خود حقی برای تصویب طرح ایجاد نمی‌کند.

  2. مجري پروژه صحت مندرجات اين پرسشنامه و پیوست­های مربوطه را تأييد می‌نماید.

  3. مجری اقرار می نماید که آئین نامه حمایت از طرح های توسعه فناوری ستاد ویژه اعضای هیات علمی را مطالعه نموده و به آنها پایبند خواهد بود(لینک آیین­نامه در سایت). در صورتی که این پیشنهاده مطابق با آیین­نامه مذکور نباشد، طرح در مرحله غربالگری رد می­شود.

  4. مجری در طول دوره پیشنهادی برای اجرای طرح در ایران بوده و برای هر گونه همکاری با ستاد طبق آئین­نامه حمایت از طرح­های توسعه فناوری آمادگی دارد.

  5. کلیه ی مطالب مندرج در این پیشنهاد طرح و پیوست های مربوطه را با هماهنگی همکاران طرح ارسال کرده است و آنها در جریان کامل طرح قرار دارند.

  6. مجری متعهد می­گردد در صورتی که هر یک از بند­های بالا در هر مرحله از اجرای پروژه نقض شود، معاونت می­تواند به صورت یک طرفه تفاهم­نامه منعقد شده را لغو نماید.

  7. این پیشنهاده طرح در 11 بند و ۲۵ صفحه بهمراه ۱۰ پیوست تهیه و از طریق سامانه خدمت معاونت علمی، فناوری و اقتصاد دانش بنیان رئیس جمهور برای ستاد توسعه فناوری های اپتیک و کوانتوم ارسال گردیده است.
