# Changelog

## 0.1.0 — 2026-11-17

اولین نسخه مفهومی (فقط مفهوم و رابط کاربری) از محصول DNS «نقطه».

* مدل داده کامل: ناحیه، مجموعه رکورد، مقدار، طرح، تاریخچه، توکن، عضو تیم،
  قالب اعمال‌شده و آمار ساعتی.
* چرخه عمر ناحیه: pending → active → suspended/deleted، با انقضای ۷ روزه و
  بازگردانی نرم.
* ویرایش رکورد با پیش‌نویس سمت کلاینت و اعمال اتمیک دسته‌ای همراه با افزایش
  سریال SOA و ثبت تاریخچه.
* اعتبارسنجی مشترک پنل/API/ORM: Punycode، TTL، A/AAAA، CNAME، MX/SPF، TXT،
  NS، SRV، CAA، PTR و سقف رکورد طرح.
* واردسازی و خروجی BIND با پیش‌نمایش تفاوت (افزودن/جایگزینی/حذف).
* DNSSEC نمایشی با ماشین وضعیت و رکورد DS قابل کپی.
* قالب GitHub Pages با پارامترهای اعلانی، پیش‌نمایش تعارض‌ها و اعمال ایدمپوتنت.
* پنل مشتری `/point` در پوسته `burna_layout` با RTL کامل، حالت تاریک و ارقام
  فارسی/تاریخ جلالی.
* پیشخوان کارکنان `/point/staff` برای جست‌وجو، تعلیق و رفع تعلیق.
* REST API نسخه‌دار `/api/point/v1` با توکن Bearer، pagination و
  `application/problem+json`.
* منوهای بک‌اند برای ناحیه‌ها، طرح‌ها، تاریخچه، توکن‌ها، اعضا و آمار.
* داده نمایشی برای داشبورد و آزمون‌های واحد پایه.

## اصلاحات پس از انتشار ۰٫۱ (۱۲۴/۰۸/۱۴۰۵)

* نمودار تقسیم نوع پرسمان در تب «آمار» دیگر خطای قالب‌بندی نمیدهد
  (`t-attf-style` جای `t-att-style` با `%%`).
* بازگشت بی‌پایان در `write()` مدل `point.rrset` برطرف شد (به‌روزرسانی
  `updated_at` از طریق `super()`).
* توکن API تازه در پیشخوان فقط یک‌بار نمایش داده میشود (حلقهٔ هدایت
  سشن دوباره مصرف میکرد).
* قالب GitHub Pages با پارامترهای یکسان، ردیف `point.template.application`
  تکراری نمیسازد و «به‌روزرسانی زمان اعمال» شناسه قبلی است.
* ADV: هشدار ناسازگاری `compute`/`store` توکن API برطرف شد (`scope_list`
  محاسبهٔ جداگانه دارد).
* تب آمار/قالب پیش از ثبت فرم هم پیش‌نمایش تفاوت را نشان میدهند.

* صفحهٔ قالب با پارامترهای درونی (مثل `?username=octocat`) هم پیش‌نمایش تفاوت و
  فرم «اعمال» را نشان میدهد؛ پیش از این فقط مقادیر پیش‌فرض محاسبه میشد.

## وضعیت تأیید

* نصب در اُدُو ۱۹ با داکر (`odoo:19` + `postgres:16-alpine`) موفق.
* ۱۰ آزمون واحد: ۰ خطا، ۰ شکست.
* همهٔ مسیرهای پوستهٔ `/point` (پیشخوان، ساختهٔ ناحیه، ۶ تب جزئیات، واردسازی،
  قالب‌ها، تنظیمات، پیشخوان کارکنان) کد ۲۰۰ بدون خطای QWeb.
* `/api/point/v1/...` با توکن Bearer آزمون شد؛ جداسازی مستأجرها تأیید شد
  (۴۰۴ برای ناحیهٔ مستأجر دیگر).

## ۰٫۱ — همسویی با فاز ۰ کتابچهٔ راهنما V4

* منوی کنار: «ناحیه جدید» اضافه شد؛ نام‌ها به واژهنامهٔ کتابچه نزدیک شدند
  («ناحیه‌ها و رکوردها»، «امنیت و رمزنگاری»، «پیشخوان کارکنان»). همهٔ
  قابلیتهای نقطهٔ DNS زیر شاخهٔ «نقطه» قرار دارند.
* صفحهٔ قالب‌ها: یادداشت محدودیت فاز ۰ و برچسب «فاز ۱+ · بهزودی» برای
  قالب‌های آینده (حذف نشده، غیرفعال نشان داده میشوند — قاعدهٔ UI کتابچه).
* صفحهٔ «امنیت و رمزنگاری»: کارت «سیاست رمزنگاری» (فقط نمایش) با کانالهای
  X25519MLKEM768 و ردیفهای غیرفعال فازهای ۱ تا ۵.
* مستندسازی: بخش دامنهٔ فاز ۰ بر پایهٔ `point-handbook_v4.html` در README.

## ۰٫۱ — زیرمنوی نقطه در نوار کناری

* `burna_layout`: شاخههای دارای فرزند اکنون به شکل زیرمنوی باز/بستهشو رندر
  میشوند (سرتیتر با šipmark و کلاس `burna-nav-group` + پنل `burna-nav-sub`)،
  بهجای فهرست صاف. گروه وقتی روی صفحههای داخل شاخه باشیم خودکار باز است.
* «نقطه» در نوار کناری: داشبورد، ناحیهها و رکوردها، ناحیه جدید، تیم،
  توکنهای API، امنیت و رمزنگاری و پیشخوان کارکنان همه زیر این زیرمنو.

## ۰٫۱ — اتصال به موتور PowerDNS (اختیاری)

* سرویس جدید `services/pdns_client.py`: کلید باریک REST برای PowerDNS
  Authoritative (`/api/v1`) — ساخت/حذف ناحیه، PATCH rrsets (REPLACE/DELETE)،
  خروجی ناحیه، DNSSEC CSK (الگوریتم ۱۳ `ecdsa256`) و DS.
* فیلدهای موتور روی `point.zone`: `engine` (mock|pdns، پیش‌فرض mock)،
  `engine_synced_at`، `engine_last_error`، `engine_ds_digest`،
  `engine_key_tag`؛ `_engine_push()` حالا هر دو موتور را پشتیبانی می‌کند و
  خطاهای موتور در `engine_last_error` و لاگ `engine.error` ثبت می‌شوند.
* `apply_changes()` بار موتور را پیش از تغییر دیتابیس عکس‌برداری می‌کند (باگ
  حذف رکورد رفع شد) و سپس به موتور ارسال می‌کند.
* UI: کارت «موتور DNS» در تب تنظیمات ناحیه (انتخاب موتور + «آزمایش اتصال» +
  آخرین هم‌گام‌سازی/خطا/DS) و کارت «موتور PowerDNS» در «امنیت و رمزنگاری»
  (آدرس API و کلید، ذخیره/پاک‌کردن/آزمایش، فقط کارکنان).
* هویت موتور نمایشی پیش‌فرض است؛ برای اتصال واقعی، API موتور باید از شبکهٔ
  بیرون قابل دسترسی باشد (در حال حاضر روی `127.0.0.1:8081` داخل VM است).

## ۰٫۱ — آزمون‌ها و نمای موتور در بک‌آفیس

* `tests/test_pdns.py`: ۱۲ آزمون — بار ایجاد/جایگزینی/حذف rrsets، خطای ۴۰۱ و
  خطای شبکه به پیام فارسی، اتصال ناحیهٔ نمایشی بدون فراخوانی کلاینت، ارسال
  batch در موتور pdns و ثبت `engine_synced_at`، ثبت خطای موتور بدون شکستن
  تغییر Odoo، آزمون اتصال، و چرخهٔ DNSSEC با کلید CSK الگوریتم ۱۳ + DS.
* `services/pdns_client.py`: `_cryptokeys()` مشترک (پردازش پاسخ
  `{"cryptokeys": [...]}`)، `_parse_ds()` در مدل برای جدا کردن key tag از
  digest رشتهٔ DS.
* نمای backend: ستون/فیلدهای موتور (`engine`, `engine_synced_at`,
  `engine_last_error`, `engine_key_tag`, `engine_ds_digest`).
